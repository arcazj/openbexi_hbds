# OpenBEXI HBDS 2.7

Version 2.7 adds a compact, live Query workspace based on the legacy HBDS functors,
consistent panel styling, and Windows installers with an offline Python runtime.

## Query and interface changes

- Query opens beside the current diagram, including unsaved edits. A searchable
  model selector also opens saved Models and Tests in a separate preview.
- Choose a legacy functor and its typed inputs on one compact row. Results update
  immediately, with visible functor descriptions, compatible added steps and pagination.
- The builder implements **21 canonical functors**. The reference documents all
  **141 legacy functors**; it does not imply that every functor is executable.
  `CONT` returns direct classes of a hyperclass, `CONTN` includes nested classes,
  `HCONT` returns direct hyperclasses, and `COUPLE` follows directed class links.
- Results contain Type, Name and Locate. Locate all follows the result filter across
  pages. Fluorescent yellow text and link highlights preserve diagram pan and zoom.
- Models, Edit, Tests, Query and Help share compact controls and soft section colors.
  The connection indicator sits beside the square tree control.
- The unused Java/Maven starter has been removed. The application uses Python and
  browser JavaScript.

## Installation and upgrades

Install for the current Windows user, then open **OpenBEXI HBDS** from the Start menu.
Core viewing, editing, querying, saving and API documentation work offline.
External AI services and external model assets still need network access.

Models, backups and logs are stored separately in `%LOCALAPPDATA%\OpenBEXI\HBDS`.
Upgrades preserve edited models and intentionally deleted examples. Uninstallation
preserves the user data folder. The launcher reuses an existing session and selects
a free local port when port 8010 is occupied.

The release includes automated package checks on native x64 and ARM64 runners for
installation, startup, offline browser rendering, API save/reload, repeated launch,
upgrade and uninstallation. Windows 10 is a compatibility target; a separate native
Windows 10 desktop acceptance test is not part of the hosted checks.
