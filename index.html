HBDS Help

What Is HBDS Graphic Simulator

An interactive browser-based simulator for Hypergraph-Based Data Structures (HBDS). The app renders HBDS models as editable 2D diagrams and optional 3D scenes using Three.js.

User Guide

Open And Navigate

  • Use Models for read-only exploration, Edit for files saved under models/, and Tests for regression files saved under test_models/.
  • Select a model from the model list, then use Fit Model, zoom, pan, the 2D/3D toggle, and the overview to inspect it.
  • Use the model tree to find classes, hyperclasses, attributes, and links by name or ID.

Edit Models

  • In Edit or Tests, create and update hyperclasses, classes, attributes, and links from the left-side controls.
  • Drag class and hyperclass nodes on the canvas, use layout controls to organize the diagram, and use route presets for selected links.
  • Use the selected link property panel to choose arrow type, arrow direction, line style, line width, line color, arrow color, and label size. Supported arrows include filled, outline, chevrons, dotted, bar-arrow, cone, diamond, bidirectional, and plain association styles.
  • Use Settings > Font for the overall model font size, then override class, hyperclass, attribute, or link label sizes separately. Apply Overall Font To All clears category and element font-size overrides.
  • Use Save to persist the current model, or Delete Model to remove the selected saved file after confirmation. Deleted models are backed up under the matching .backups directory.

Query the Model

  • Open Query between Tests and Help to capture the entire current diagram, including unsaved edits, nested nodes, and hidden elements. The editor stays open with its selection and undo history.
  • Query initially uses the model already selected in Models, Edit, or Tests. The searchable model selector beside Query groups the current session, Models, and Tests. Selecting a saved model opens a separate diagram preview. Selecting the current session or leaving Query restores the original model, unsaved edits, selection, and undo history.
  • Choose a functor, then fill its searchable inputs on the same row. Its description stays visible below the selectors and in its tooltip. ATT asks for a class; HATT asks for a hyperclass. Valid selections update results immediately. Typing in a dropdown filters its choices; selecting an option commits it.
  • COUPLE asks for source and target classes and returns links directed from source to target. PSC returns outgoing links; FIN returns their target classes. Add step offers compatible continuations, such as PSC then FIN then ATT, and collects any required parameters. CARD counts the complete result.
  • CONT returns a hyperclass's directly included classes; CONTN includes classes at every nesting depth; HCONT returns directly included hyperclasses. CONTOF and HCONTOF return direct containing hyperclasses. Queries use explicit memberships when a semantic layer exists, otherwise the model's declared parent/child containment.
  • Query opens in a 400-pixel sidebar beside the diagram; on narrow screens, the diagram appears above it. Results show only Type, Name, and Locate. Name tooltips show identifiers and paths; selecting a name opens its stored data.
  • Locate highlights the result text and link route in fluorescent yellow. Locate all highlights all results matching the Results filter across every page. Both preserve the diagram's position and zoom, the editing selection, and undo history. Highlights clear when the query, filter, or source changes, or when Query closes.
  • Switching models retains compatible functors, clears model-specific selections and filters, and returns results to page one. The new preview is fitted once when loaded; Locate keeps its camera unchanged. Source changes refresh results automatically while preserving valid inputs. Results use 25 rows per page by default, with 50 and 100 also available. Read-only queries and model switching also work from the app in static mode.
  • The searchable reference lists all 141 documented functors with source pages and availability; 21 are implemented for recorded metamodel definitions. Selectors use only original functor names. Inherited definitions, object data, and mixed class/hyperclass links are outside this subset. Unavailable operations are identified explicitly.
  • The connection indicator is at the upper left, immediately before the square tree toggle. The tree control is available in Edit and Tests; hover or focus the connection indicator for its status.

Collaboration

  • When the local server is connected, other browser tabs on the same model appear in Live Collaboration.
  • Review remote changes before saving. Use Merge Both for safe non-conflicting edits, Use Theirs to accept the selected remote draft, or Keep Mine to keep your local version.

AI Support

  • Open AI Support in Edit or Tests to generate, validate, improve, repair validation errors, explain a selection, or improve selected classes and links. Focused edits preserve unrelated entities and existing positions.
  • Select ChatGPT/OpenAI, Claude/Anthropic, Local/Ollama, Custom OpenAI-compatible, or ChatGPT / Manual. API keys entered in the UI are held in memory only and are not saved into model JSON.
  • ChatGPT / Manual prepares a precise HBDS prompt for copy/paste into ChatGPT, then lets you paste the JSON response back for validation.
  • Valid AI responses must be plain JSON with metadata, hypergraph.class, hypergraph.link, valid IDs, valid link references, and usable positions.
  • Refresh Available Models checks the provider's model list without generating text. Keys stay in memory. Editing requests send the current model for context; provider charges may apply when you send a request.
  • Apply AI Result opens a review with a checkbox and before/after details for each change. Related changes must leave a valid model. Preview on Canvas shows the selected changes without saving, Apply and Save updates the current file, and Apply as New Model creates a new file.
  • If the model changes while an AI request is pending, send a new request before applying its result. Cancel stops waiting locally; an already-sent provider request may still finish and incur charges.
  • Rollback AI Apply restores the previous saved model after same-file changes, or deletes the newly-created AI model after Apply as New Model.

Why HBDS

HBDS means Hypergraph-Based Data Structure.

It is a data modeling and knowledge representation method created by François Bouillé, mainly developed in France around the 1980s-1990s for advanced information systems, GIS, scientific databases, and complex semantic structures.
